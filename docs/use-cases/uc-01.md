# UC-01 — Dev wraps a package (UF-02)

**Persona:** Dev — wraps Python packages into sandboxed MCP tools conversationally.
**Goal:** run the package converter end-to-end and prove the AI-judge gate is
fail-closed: with no Token Factory key the conversion is **rejected** with a
machine-readable record; with the demo (stub) judge it auto-merges.

## Commands

```bash
./scripts/test-uc-01.sh            # automated use-case script (hermetic, offline)

# Manual equivalents:
export PROTOX_DATA_DIR=$(mktemp -d /tmp/protox-data.XXXXXX)
export PROTOX_WORKSPACE=$(mktemp -d /tmp/protox-ws.XXXXXX)
unset PROTOX_TF_API_KEY            # degraded mode: judge fails closed

uv run protocol-x-tool-mcp convert textwrap        # expect exit 2 + REJECTED
uv run python agents/converter_agent.py textwrap --judge pass   # stub judge: merges
```

## Expected output (excerpt)

Fail-closed production run (this is the **correct** degraded behavior, E-20/E-10):

```
degraded mode (E-20): PROTOX_TF_API_KEY not set — the AI-judge fails closed, ...
REJECTED: judge-blocked-unrepairable: judge blocked and no repair approach applies — conversion rejected (E-10)
rejection record: .../conversions/textwrap-<ts>/rejection.json (run 1)
```

The rejection record and the `conversion_runs` SQL row both carry
`reason_code=judge-blocked-unrepairable`. The stub-judge demo path ends with:

```
OBSERVE  auto-merged textwrap.py → tools live (simulated)
verdict=pass fix_cycles=0 judge_cycles=1
tools: textwrap_dedent, textwrap_indent
```

## What verifies what

- Rejection exit code + message → judge fails closed without a key (INV-6).
- `rejection.json` + `conversion_runs` row → terminal outcomes are auditable (F-029).
- Demo merge → the full pipeline (introspect → propose → codegen → format → judge → merge) works with a passing verdict.
